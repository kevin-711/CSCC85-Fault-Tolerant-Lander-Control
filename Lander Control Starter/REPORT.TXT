3) Describe your strategy for dealing with thruster failures

In case of thruster failure, we choose one working thruster to be the primary. We then steer the lander by tilting left/right and thrusting while we descend

4) Describe your strategy for dealing with sensor malfunctions:

   - Position sensors
  For the position sensors, we kept if track of the velocity and created an estimated time for each iteration and calculated the change of position based on that. On top we also used the RangeDist() along with the angle that lander is turned to measure distance because of the case where the velocity sensors are also failing.
   - Velocity sensors
To deal with failing velocity sensors, we took samples of the position through iterations and kept that in an array of oldest to newest readings. Then we average the first couple of readings and the last couple of readings and use the difference to calculate the slope using our DT value which is an estimate of time and calculate the velocity. Note we are using the position values after estimating the position value in the case the position sensors failed. 
   - Angle
To deal with an angle sensor failing, we keep in track of how much we turned so far. SO basically we are keeping history of how much we turned and based on that awe are calculating our current angle of the lander.
   - Sonar
For the instance where the Sonar sensor fails, based on the current working thruster we calculate how much we turned to get angle and that angle relative to the main thrusters current angle using rangedist would give us an estimate close to sonar.
